# RESEARCH — 既存タイピング練習ソフトの分析と本アプリの設計根拠

本書は Kaede Typing（`/home/user/typing`）の設計判断の背景をまとめた文書である。
実装契約は `docs/ARCHITECTURE.md` にあり、本書はそれを「なぜそうしたか」の側から補う。
記述は原則として本リポジトリの実装（`src/core/*.js`, `src/ui/*.js`）に紐づける。
外部製品についての記述は、確実に言えることだけを書き、確信が持てない点は「推測」と明示する。

---

## 1. なぜ作るのか

### 1.1 問題意識

タイピング練習は「短時間・毎日・気が向いたとき」に成立する必要がある。
ところが練習環境の側に、その成立を妨げる要素が多い。

| 妨げ | 具体的に起きること |
| --- | --- |
| 広告 | 1 レッスン終わるたびに画面が切り替わる。職場や教室では表示内容が制御できない |
| 課金導線 | 「続きは有料」で練習が途切れる。子供が自分で判断できない |
| アカウント必須 | 初回に登録が必要で、その場で始められない。学校では一括管理が要る |
| 外部送信 | 打鍵ログが手元を離れる。職場の端末で使いにくい |
| オンライン必須 | 回線が細い環境・オフライン端末で使えない |
| 目立つ画面 | 職場のディスプレイで「遊んでいる」ように見え、続けにくい |

### 1.2 本アプリの立場

- **広告なし・課金なし・アカウントなし**。保存は `localStorage` のみ（`src/core/store.js`）。
  サーバへ送るものは何もなく、送信コードも持たない。
- **依存ゼロ**。npm / CDN / 外部フォント / 外部画像 / `fetch` を使わない。
  ファイルを置くだけで動く。オフラインでも、社内共有フォルダでも、USB からでも動く。
- **1 分から練習できる**。ホームから 1 クリックで適応練習が始まる（`src/ui/shell.js` → `src/ui/adult.js`）。
- **2 つの読者**。仕事中に短く自己研鑽したい大人（`adult.js`）と、
  続ける動機づけが要る子供（`kids.js`）。同じエンジンの上に別の皮を被せる。

### 1.3 「使える場所」を設計条件にする

- 職場 … 音を出さない、動きを出さない、彩度を落とす、画面を業務アプリ風にする（4 章）。
- 教室 … 1 台に複数人が座ってもアカウント登録が要らない。
  データは端末内で完結し、書き出し／読み込みで移せる（`store.exportJSON` / `importJSON`）。
- 家庭 … 保護者が課金や広告を心配しなくてよい。休憩リマインダーを既定で有効にする。

## 2. 既存ソフトの分析

各項目は「確実に言えること」に絞る。料金体系や広告の有無は変わりやすく、
確認できていないものは **推測** と明記する。

### 2.1 一覧表

| ソフト | 種別 | 優れている点 | 足りない点（本アプリの用途から見て） | 本アプリの扱い |
| --- | --- | --- | --- | --- |
| keybr.com | Web / 適応練習 | 少数の文字から始め、習熟に応じて1文字ずつ解禁する。文字集合から発音可能な擬似語を生成し、キー別の速度・正確率を蓄積して弱点を厚く出題する | 擬似語中心で実在語への転移が薄い。日本語ローマ字入力の「かな単位」の概念がない | **取り込む**：解禁方式・擬似語生成・キー別統計。`curriculum.maybeUnlock` / `generator.pseudoWords` / `pseudoKana`。**足す**：`real` 行で実在語・実文を混ぜる |
| Monkeytype | Web / 計測寄り | 極端に簡素な画面。時間・語数モード、結果に WPM・正確率に加えて一貫性（consistency）を出す。設定項目が豊富 | 学習順序を持たない。初心者を「何から練習するか」導かない | **取り込む**：一貫性指標と簡素な画面（`engine.js` の `consistency`、`plain` スキン）。**捨てる**：設定の多さ。設定は1画面に収める |
| TypingClub | Web / 教育向け | 体系的なレッスン順。学校導入を想定した進度管理 | 進捗がアカウントに紐づく（推測を含む）。教材が固定で、個人の弱点に合わせた再出題は弱い | **捨てる**：アカウント前提。**取り込む**：段階的なレッスン順は子供モードのステージ構成に反映（`buildStageLesson`） |
| Typing.com | Web / 教育向け | 無料で広範なレッスンとゲーム。教師向け機能 | 無料利用では広告が表示される（推測）。職場・教室で画面内容を制御できない | **捨てる**：広告。**取り込む**：レッスンとゲームの二層構造（大人＝レッスン、子供＝ステージ） |
| Nitro Type | Web / 対戦ゲーム | レースという明快な目標。車などのコレクション要素で継続動機を作る | 競争・収集が主目的化しやすい。対戦のためオンラインとアカウントが要る | **捨てる**：対戦とオンライン。**取り込む**：コレクション（`store.profile.pets`、600打鍵ごとに1匹） |
| TypeRacer | Web / 対戦 | 実在の文章を打つため転移が高い。他者との比較が動機になる | 題材に著作物からの引用が含まれる。オンライン必須 | **捨てる**：他者との対戦と引用文。**取り込む**：実文を打つ設計（`JA_SENTENCES` / `EN_SENTENCES` は自作文とことわざのみ） |

| 寿司打 | Web / ゲーム（日本語） | 回転寿司という分かりやすい枠。制限時間内に打ち切る緊張感。日本語ローマ字入力を正面から扱う | 練習というより計測・遊び。キー別の弱点分析や解禁順を持たない | **取り込む**：時間制限モード（`timeLimitMs`、大人の60秒計測、子供のボス戦）。**足す**：弱点分析 |
| e-typing | Web / 練習＋計測（日本語） | ローマ字入力の題材が豊富。スコア表示とランキングで励みになる | 日々の弱点に合わせた自動出題や解禁の概念は薄い（推測）。広告あり（推測） | **取り込む**：日本語題材の作り方（語・短文・ことわざ）。**捨てる**：ランキングと広告 |
| myTyping | Web / 投稿型（日本語） | 利用者が課題を投稿でき、題材が尽きない | 題材の質と権利関係が投稿に依存する。学習設計は投稿者任せ | **捨てる**：投稿機構。**取り込む**：題材をデータ（`src/data/*.js`）に分離し、差し替え可能にする発想 |

| Epistory | 商用ゲーム | 物語と打鍵を統合し「練習している感じ」を消す | 有償。練習指標が目的ではない | **取り込む**：物語性の薄い版としてステージマップ。**捨てる**：ゲーム本体の重さ |
| Mavis Beacon | 商用ソフト（古典） | 運指指導・進捗管理を早期から体系化した。手の図の提示 | 商用パッケージ。Web で今すぐ、という要求に合わない | **取り込む**：手の図（`keyboard.js` の `HandsView`、inline SVG）と運指色分け（`layouts.js` の `FINGER_COLOR`） |
| Typesy | 商用ソフト | レッスンと進捗管理を一体にした学習プログラム（推測を含む） | 有償。ここで確実に言えることが少ない | 参考にとどめる |
| ZType | Web / ゲーム | 単語を打って撃ち落とす。ルールが一瞬で分かる。無料 | 弱点分析や解禁は持たない。記号・日本語は扱わない | **取り込む**：ルールの説明不要さ。子供モードのステージは説明文を最小にする |

### 2.2 分析から取り出した5つの結論

1. **適応（keybr 型）とゲーム（Nitro Type 型）は排他ではない。** 同じ統計の上に別の見せ方を載せればよい。
   本アプリは `engine.js` / `store.js` / `curriculum.js` を共有し、`adult.js` と `kids.js` で表示だけ変える。
2. **実在語を打たせないと転移しない。** 擬似語だけでは速くなっても文章が打てない。
   `planSession()` が `real` 行を必ず混ぜる。
3. **日本語は「かな単位」で考える必要がある。** 英語の WPM だけでは日本語の上達が見えない。
   `kpm`（かな毎分）を別に出す。
4. **題材は権利的に安全な自作に限る。** 引用を使う既存サービスの真似をしない。
   `src/data/ja.js` などは自作の平易文とことわざのみ。
5. **続かない最大の理由は環境**。広告・課金・アカウント・目立つ画面のどれか1つで練習は止まる。
   4 章の「目立たないモード」はこの結論から出ている。

## 3. 最短習得のための原則

以下は運動学習・練習理論の一般的な知見として広く語られている事柄である。
特定論文の具体的数値は引かない。断定できないものは「一般に〜とされる」と書く。

### 3.1 原則と実装の対応表

| 原則 | 根拠（一般論として） | 本アプリでの実装箇所 |
| --- | --- | --- |
| 正確性を速度より先に | 誤った運動パターンも反復すれば定着してしまうため、速度を先に上げると後から矯正が要る、と一般にされる | `strict=true` の強制訂正（`engine.js` `input()`）／XP が精度の2乗（`store.finishSession`） |
| 少数から始めて解禁 | 一度に扱う要素を絞ると認知負荷が下がり、各要素の反復回数が稼げる | `curriculum.seedSize` / `unlockedChars` / `maybeUnlock` |
| 弱点の狙い撃ち | 出来ることを繰り返しても伸びない。苦手に時間を割いた方が効率が良いとされる | `store.weakness()` → `curriculum.charWeights()` / `weakestChars()` / `generator.buildDrillLesson` |
| インターリーブ | 同じ課題を固めて練習（ブロック練習）より、混ぜた方が定着が良いとされる | `curriculum.planSession()` |
| 分散学習・短時間反復 | 同じ総時間なら、まとめてより分けた方が定着しやすいとされる | `store.profile.streak` / 連続日数表示 / `breakReminder` |
| 即時フィードバック | 誤りは直後に知らせるほど修正されやすいとされる | 1打鍵ごとの `onUpdate`、`KeyboardView.flash()` の `.is-hit` / `.is-miss`（180ms） |
| キーボードを見ない | 視線移動は打鍵の中断を生む。手元を見ない前提の配置記憶が必要 | 画面キーボード（`KeyboardView`）と手の図（`HandsView`）を視線の上側に置く |
| 一貫性（リズム）の計測 | 平均速度が同じでも、間隔のばらつきが大きいほど未習熟な部分が残っているとみなせる | `engine.js` `consistencyOf()` |
| 実在語への転移 | 練習が本番に近いほど転移しやすいとされる | `planSession` の `real` 行、`buildWordLesson` / `buildTextLesson` / `buildCodeLesson` |

### 3.2 正確性を速度より先に

強制訂正（`strict`）では、誤打はカーソルを進めない。
`engine.js` の `input()` は誤打時に `errors++`、`combo = 0` とし、matcher へは送らない。
`strict=false` のときだけ「本来押すべき代表文字」を自分で送って1文字進め、
誤りとして記録したうえで先へ進める。

報酬側でも精度を優先する。`store.finishSession()` の XP は

```
gained = round(keys * acc^2 * 0.8) + (acc >= 0.98 ? 15 : 0)
```

精度が 2 乗で効くため、精度 0.8 は精度 1.0 の 64% しか XP を生まない。
「速く雑に打つ」戦略が数字の上で損になるようにしてある。

キー単位でも同様で、`store.mastery()` は速度 0.45・正確率 0.35・サンプル数 0.20 の合成、
`store.isLearned()` は **正確率 92% 以上かつ平均打鍵間隔が目標の 1.25 倍以内**を要求する。
速いだけでは解禁が進まない。

### 3.3 少数から始めて解禁

- 初期解禁は日本語 6 文字、英語 4 文字（`curriculum.seedSize`）。
- 日本語の解禁順は **母音 5 つが先**（`ORDER_JA = ['a','i','u','e','o', 'k','s','t', ...]`）。
  ローマ字入力では母音が無いと1かなも打てないため、ここは英語と分ける必要がある。
- 英語は `balanced`（運指の広がりと語形成を両立）と `homerow`（伝統的な段順）を設定で選べる。
- 解禁条件は `maybeUnlock()`：解禁済みの **85% 以上が習得済み**、かつ **直近解禁した文字も習得済み**。
  片方だけでは進まないので、「新しい文字を放置したまま先に進む」ことが起きない。

### 3.4 弱点の狙い撃ち

`store.weakness(char)` は次の形をとる。

```
未知（サンプル3未満）        → 1.4      // 未知キーを優先的に出す
既知 → min(4, 0.15 + min(2, 遅さ) + (1 - 正確率) * 6)
遅さ = (平均打鍵間隔 - 目標間隔) / 目標間隔
```

正確率の係数が 6 と大きく、遅さの寄与は 2 で頭打ちになる。
**「遅い」より「間違える」方が強く出題を引き寄せる**設計である。

`charWeights()` はこの弱点スコアに、直近解禁の 2 文字へ 2.2 倍のブーストを掛ける。
新しい文字はサンプルが少なく弱点スコアも中庸になりがちなので、明示的に厚くしている。

連接（ビッグラム）単位では `store.worstBigrams()` が遅い2文字組を返し、
`generator.buildDrillLesson()` がそれを含む語だけを並べる。
統計が溜まる前（ビッグラムが取れない間）は適応レッスンへフォールバックする。

### 3.5 インターリーブ

`curriculum.planSession()` が返すレシピは固定パターンの繰り返しである。

```
['mixed', 'real', 'focus', 'mixed', 'real', 'mixed', 'focus', 'real']
```

- `focus` … 弱点文字を厚くした擬似語
- `mixed` … 解禁済み全体からの擬似語
- `real` … 実在語・実文

8 行中 3 行が `real` で、同じ種類が 3 行以上続かない。
「弱点だけ 8 行」は一見効率的に見えるが、単調で崩れやすく、
実在語への転移も起きないため採らなかった。

### 3.6 分散学習・短時間反復

- 1 セッションは既定 8 行。数十秒〜2 分で終わる。長いセッションを作らない。
- `store.profile.streak` は `finishSession()` が日付で更新し、
  前日に練習していれば +1、途切れれば 1 に戻る。ホーム画面に連続日数を出す。
- `daily['YYYY-MM-DD'] = {ms, keys, sessions}` に日別の練習量を残し、統計画面と
  子供モードのデイリーミッションの両方がこれを読む。
- `breakReminder`（既定 20 分）を超えたら休憩を促す。**続行を止めない**（閉じれば続けられる）。
  長時間やらせる方向に設計を寄せない、という判断である。

### 3.7 即時フィードバック

- `engine.js` は 1 打鍵ごと（および時間制限モードでは 100ms ごと）に `onUpdate(state)` を呼ぶ。
- `state` には `expected`（次に受理できる文字集合）が入っており、UI はこれを
  `KeyboardView.highlight()` に渡す。**複数の正解があるときは複数キーが光る**。
  これは日本語ローマ字で重要で、`し` の場面では `s` と `c` が同時に光る。
- 打鍵直後は `flash(char, ok)` が `.is-hit` / `.is-miss` を 180ms 付ける。
- `HandsView.highlight(finger, shiftSide)` が対応する指を着色する。Shift は自動で反対側が光る。

### 3.8 キーボードを見ない

手元を見る癖は「どこにあるか分からない」不安から来る。
不安を消す方法は、目線の高さに配置情報を置くことである。

- 画面キーボードは既定 ON（`settings.showKeyboard`）。
- 手の図も既定 ON（`settings.showHands`）。画像は使わず inline SVG で描く（依存ゼロの制約）。
- 指の色は `layouts.js` の `FINGER_COLOR` で統一し、凡例（`renderFingerLegend`）と同じ色を使う。
- 慣れたら両方とも設定で消せる。**消せることが目標**であり、常時表示を前提にしない。

### 3.9 一貫性（リズム）

`engine.js`：

```js
function consistencyOf(intervals) {
  if (intervals.length < 2) return 1;
  mean = 平均;
  sd = 標準偏差（母分散、n で割る）;
  return clamp(1 - sd / mean, 0, 1);
}
```

`intervals` は **正解打鍵どうしの間隔**のみで、`MAX_INTERVAL = 2000` ms で丸める
（考え込んだ時間を外れ値として切る）。
変動係数 `cv = sd / mean` が 0 に近いほど一定のリズムで打てている。

平均 WPM が同じでも、一貫性が低ければ「速く打てる部分と詰まる部分が混在している」。
詰まりの場所は `worstBigrams()` が指す。2 つの指標は組で読む前提で設計している。

### 3.10 実在語への転移

- 日本語の `real` 行は実在語を **空白なしで 3〜5 語連結**し、12〜24 かなの1行にする
  （`generator.js` `collectJa`）。日本語の文章入力は語の区切りで手が止まらないことが重要なため、
  区切り記号を入れない。
- 英語の行は 5〜7 語を半角空白で連結する。
- 実在語が解禁済み文字だけでは足りない場合、`realEntries()` が擬似語で埋める。
  **解禁されていない文字を混ぜない**方を優先する。
- 大人モードにはビジネス定型文（`BUSINESS_JA`）とコード行（`CODE_LINES`）があり、
  記号運指という実務上の弱点を直接扱える。

## 4. 大人向け「目立たないモード」の設計

### 4.1 目的の明示

この設計は、**職場で短い時間の自己研鑽を続けるための配慮**である。
就業規則に反する使い方や、監督者を欺くことを目的としない。
「練習しているところを見られるのが気恥ずかしい」「派手な画面が周囲の気を散らす」
という現実的な障壁を下げ、1 日 3 分の練習が続くようにするためのものである。
不正利用を助けるための機能（ログの改ざん、計測の偽装など）は持たない。

### 4.2 何を消すか

| 対象 | 既定 | 実装 |
| --- | --- | --- |
| 音 | 消す | `adult.js` が `sfx.enabled = false` にする。`audio.js` は `settings.sound === false` でも全 no-op |
| アニメーション | 出さない | 祝福演出・紙吹雪は子供モードのみ。`reduceMotion` 設定と `prefers-reduced-motion` を尊重 |
| 彩度 | 落とす | `assets/css/adult.css` は `base.css` のトークンを低彩度側で使う。原色を置かない |
| 絵文字 | 使わない | 文言は常用漢字。絵文字は子供モードのみ |
| 大きな結果画面 | 出さない | 終了時は WPM・正確率・一貫性・新解禁文字を落ち着いたカード1枚で出す |

### 4.3 何を擬態させるか

`settings.skin` で6種類を切り替える（`adult.js`）。

| skin | 見た目 | 置き換わるタイトル（`SPOOF_TITLE`） |
| --- | --- | --- |
| `editor` | コードエディタ風（行番号・タブバー・サイドバー） | `index.js — 作業中` |
| `docs` | 文書エディタ風（白い紙・ツールバー） | `無題ドキュメント` |
| `sheet` | 表計算風（セルグリッド。1 セル 1 語） | `集計表_2026.xlsx` |
| `mail` | メールクライアント風（一覧＋本文ペイン） | `受信トレイ` |
| `terminal` | ターミナル風（プロンプト行） | `bash — 80×24` |
| `plain` | 最小限 | `ページ` |

`spoofTitle` が有効なとき `document.title` を差し替え、favicon は
`data:image/svg+xml,...` の無地アイコンに置き換える。
**data URL なので外部リクエストは発生しない**（依存ゼロ制約と両立させるための選択）。

### 4.4 パニックキー

- `Esc` を 500ms 以内に 2 回、または `Ctrl+.` で「無害な画面」へ切替。
- もう一度同じキーで復帰。復帰時にはセッションが `pause()` 済みであることを保証する
  （隠れている間に経過時間が伸びて WPM が壊れることを防ぐ）。
- `panicOnBlur` が true のとき、`window.blur` と `visibilitychange` でも自動で切り替わる。
- パニック画面はダブルクリックでも戻せる（キーを忘れた場合の逃げ道）。

`pause()` / `resume()` は `engine.js` で経過時間を保存する実装になっている。
`resume()` は停止していた分だけ `_startedAt` と `_lastCorrectAt` を後ろへずらすので、
中断が速度・一貫性の数字を汚さない。

### 4.5 実務に寄せたメニュー

適応練習 / 弱点ドリル / 単語 / 文章 / ビジネス文 / コード / 60秒計測。
「ビジネス文」と「コード」は、実務で実際に打つ文字列（敬語定型・記号列）を扱うための行であり、
遊びの追加ではなく転移のための行である。

## 5. 子供向けゲーミフィケーションの設計

### 5.1 使う動機づけ要素

| 要素 | 実装 | 意図 |
| --- | --- | --- |
| 進捗の可視化 | ステージマップ（24マス）、XPバー、レベル、★1〜3 | 「あとどれだけ」を常に見えるようにする |
| 即時フィードバック | 打鍵ごとの色、コンボメーター、効果音（`sfx`） | 1打ごとに手応えを返す |
| 変動報酬 | 600打鍵ごとに仲間が1匹ふ化（`store.profile.petProgress`） | 次がいつ来るか読めないので、続ける理由が残る |
| コレクション | `store.profile.pets` の図鑑 | 「集まっていく」ことが練習量の記録そのものになる |
| 適切な難易度 | `buildStageLesson({stage})` が段階的に文字を増やす | 簡単すぎず難しすぎない位置を保つ |
| 明確な山場 | 5 ステージごとにボス（制限時間つき、HP = `1 - metrics.progress`） | 区切りと達成感を作る |
| 日次の小目標 | デイリーミッション3つ（打鍵数 / 正確率 / ステージクリア） | 「今日やる理由」を毎日作る |

ステージ構成は `buildStageLesson` 側で決まる。
英語は 1〜6 がホームポジション（`fjdk` から `asdfghjkl` へ）、7〜12 が上段、13〜16 が下段、17 以降が総合。
日本語は行単位で増やし（あ行…ま行 → や行…だ行 → ば行・ぱ行・拗音）、17 以降は全かな。

★の判定は `engine.js` の `gradeOf()`：

| 条件 | ★ | 表示 |
| --- | --- | --- |
| 正確率 < 70% | 0 | もういちど |
| 正確率 ≥ 95% かつ WPM ≥ 目標の 80% | 3 | かんぺき |
| 正確率 ≥ 90% | 2 | じょうず |
| それ以外 | 1 | クリア |

**★0 でも「もういちど」であって「失敗」ではない**。文言レベルで罰を軽くしている。

### 5.2 やりすぎない設計

ゲーミフィケーションは、やりすぎると「練習」ではなく「消費」になる。
以下は意図的に **入れなかった／弱めた** ものである。

| 入れないもの | 理由 |
| --- | --- |
| 課金・ガチャ・通貨 | 子供が自分で判断できない仕組みを置かない。そもそも決済コードを持たない |
| 広告・外部リンク | 画面内容を制御できなくなる |
| 他人との順位表 | 遅い子が離脱する。比較対象は過去の自分だけにする |
| 連続記録を失う演出 | ストリークが切れても責めない。`streak` は静かに 1 に戻るだけ |
| 強い敗北演出 | ミスは画面が小さく揺れるだけ。効果音も短い |
| 無限に続くセッション | 1 ステージは短く終わる。`breakReminder` 分を超えたら「ちょっと休もう」を出す |

演出は `<canvas>` への自前描画（紙吹雪）で、色は CSS 変数から読み 2 秒で消える。
`settings.reduceMotion` が true、または `prefers-reduced-motion` のときは描画しない。
効果音は `audio.js` の Oscillator 合成のみで、外部ファイルを持たない（1音 120ms 以内）。

### 5.3 報酬は「練習量」に紐づける

仲間のふ化は打鍵数 600 ごとで、精度や速度には依存しない。
一方 XP は精度の 2 乗で効く。

- **量の報酬（ふ化）** … 続ければ必ず来る。上手くない子も取り残さない。
- **質の報酬（XP・★）** … 丁寧に打つほど伸びる。

2 系統に分けることで、「下手だから何も貰えない」状態を作らない。

## 6. 測定指標の定義

以下はすべて `src/core/engine.js` の実装そのままである。

### 6.1 定義

| 指標 | 定義 | 備考 |
| --- | --- | --- |
| `correct` | 正しく受理された打鍵数 | matcher が `ok:true` を返した回数 |
| `errors` | 受理されなかった打鍵数 | `strict=false` の強制前進も誤りとして数える |
| `keys` | `correct + errors` | 総打鍵数 |
| `wpm` | `(correct / 5) / (elapsedMs / 60000)` | グロス WPM。1語 = 5打鍵の慣例 |
| `cpm` | `correct / (elapsedMs / 60000)` | 1分あたりの正打鍵数 |
| `kpm` | 日本語: `確定かな数 / 分`、英語: `cpm` と同値 | かな毎分。日本語の実感に近い |
| `accuracy` | `correct / (correct + errors)`、打鍵0なら1 | 0..1 |
| `consistency` | `clamp(1 - sd/mean, 0, 1)`、サンプル2未満は1 | 正解打鍵間隔の変動係数から |
| `elapsedMs` | **最初の打鍵**から現在まで。`pause` 中は進まない | `start()` では計測を始めない |
| `progress` | `(完了行の最短打鍵数 + 現在行の打鍵数) / 全行の最短打鍵数` | 0..1 |

### 6.2 なぜこの定義か

- **グロス WPM を採る。** 誤打を差し引くネット WPM は「速度」と「正確性」を1つの数に潰してしまう。
  本アプリは正確性を `accuracy` として独立に見せ、XP 側で精度に重みを付ける方針なので、
  速度の数字は素のままにしておく。
- **`kpm` を別に持つ。** 日本語ローマ字では 1 かなに 2〜3 打鍵かかる。
  WPM だけを見ると「英語より速い／遅い」の解釈が破綻する。
  `_kanaUnits` は matcher の `unitIndex` の増分を積み上げたもので、**確定したかな数**を数える。
- **間隔は正解打鍵のみ。** 誤打を含めると、強制訂正モードで同じキーを連打したときに
  間隔分布が壊れる。
- **2 秒で丸める。** `MAX_INTERVAL = 2000`。考え込んだ時間を含めると、
  一貫性も平均打鍵間隔も「どれだけ迷ったか」の指標になってしまう。
  `store.recordKeystroke()` 側でも同じ 2000ms の丸めをしている。
- **最初の打鍵は記録しない。** 間隔が定義できないため（`_lastCorrectAt == null` のとき skip）。

### 6.3 キー別統計の更新則

`store.recordKeystroke({expected, ok, ms, prev})`：

- 正打 … `n++`、`ms` を指数移動平均で更新（`alpha = max(0.12, 1/max(2, n))`）、`best` を更新。
  直前の正解文字があれば `bigrams[prev + expected]` も更新。`totalKeys++`。
- 誤打 … `err++` のみ。**時間は記録しない**（誤打の時間はキーの速度を表さないため）。
- 誤打時の `expected` は「本来押すべきだった代表文字」で、
  `engine.js` の `_representative()` が `remaining()[0]` を優先して決める。
  複数正解があるローマ字でも、記録先が1つに定まる。

alpha に下限 0.12 を置いているのは、サンプルが増えても直近の実力に追随させるためである
（過去1000打鍵の平均に固定されると、上達が指標に出なくなる）。

## 7. 日本語ローマ字入力の難しさと本実装の方式

### 7.1 何が難しいか

英語の入力判定は「次の1文字が一致するか」で済む（`DirectMatcher`）。
日本語ローマ字はそうならない。

| 難所 | 例 |
| --- | --- |
| 1かなに複数のつづり | `し` = `si` / `shi` / `ci` |
| 拗音の融合と分解 | `きゃ` = `kya` / `ki` + `xya` / `ki` + `lya` |
| 撥音の分岐 | `ん` = `n` / `nn` / `xn` / `n'`（`n` 単独は条件つき） |
| 促音の子音重ね | `っ` = 次の頭子音の重ね / `xtu` / `ltu` |
| 判定が後ろに依存する | `n` が正しいかどうかは**次のかな**が決めてしまう |

最後の項目が本質である。逐次的に「この1文字は正解か」を決められない場面があるため、
単純な前方一致では破綻する。

### 7.2 本実装の方式 — 非決定性オートマトン

`src/core/romaji.js` は「生きている状態の集合」を保持する。

```js
状態 = { i: かな位置, buf: 現セグメントに入力済みの部分文字列 }
```

`feed(ch)` は全状態を 1 文字ぶん延長し、**1つでも生き残れば正解**とする。
生き残りが 0 になったときだけ誤打である。

```js
this.unitIndex = Math.min(...this.states.map((s) => s.i));
```

表示カーソルは「全状態が到達済みの最小位置」＝**確定したかな位置**を指す。
複数のつづりを同時に追っている間はカーソルが進まず、経路が1つに絞られた時点で進む。
この `unitIndex` の増分が `engine.js` の `kpm` の分子になる。

`expected()` は全状態から「次に受理できる文字」を集める。
`しゃしん` の先頭では `{c, s}` が返り、UI ではその2キーが同時に光る。

### 7.3 「ん」の単独 n が許される条件

`segmentsAt()` の該当部分：

```js
if (ch === 'ん') {
  const nxt = kana[i + 1];
  const soloOk = nxt === undefined
    || !(VOWEL_KANA.has(nxt) || NA_GYO.has(nxt) || YA_GYO.has(nxt) || nxt === 'ん');
  return [{ romaji: soloOk ? ['n', ...BASE['ん']] : BASE['ん'], len: 1 }];
}
```

`nn` / `xn` / `n'` は常に受理。単独 `n` は **次が母音・な行・や行・ん のいずれでもないとき**だけ許す。
実際の IME と同じく、次に来る文字が `n` を吸収してしまう場合を排除している。

実機で確認した挙動（`RomajiMatcher` を直接動かして検証済み）：

| かな | 最短打鍵数 | 最短つづり | 受理される例 | 受理されない例 |
| --- | --- | --- | --- | --- |
| しんぶん | 6 | `sinbun` | `sinbun` / `shinbunn` / `sinnbunn` | `shimbun`（ヘボン式の m は非対応） |
| こんにちは | 10 | `konnnitiha` | `konnnitiha` / `konnnichiha` | `konitiha`（`ん` の次が `に` なので単独 n 不可） |
| きんようび | 9 | `kinnyoubi` | `kinnyoubi` | `kinyoubi`（次が `よ` = や行） |

`しんぶん` で `si` まで打った時点の `expected()` は `{n, x}`、`remaining()` は `nbun`。
`ん` の次が `ぶ` なので単独 `n` が生きており、最短経路として `n` 1 打鍵が提示される。

### 7.4 促音の子音重ね

```js
if (ch === 'っ') {
  segs.push({ romaji: BASE['っ'], len: 1 });          // xtu / ltu / xtsu / ltsu
  for (const next of segmentsAt(kana, i + 1, depth + 1)) {
    for (const r of next.romaji) {
      if (CONSONANT.test(r)) doubled.push(r[0] + r);   // って → tte
      if (r.startsWith('ch')) doubled.push('t' + r);   // っちゃ → tcha
    }
  }
}
```

- `CONSONANT = /^[bcdfghjkmpqrstvwxyz]/` で **`n` を除いている**。
  `んな` と `っな` の衝突を避けるため（`っ` の後にな行は重ねない）。
- `ch` で始まる場合だけ `t` 前置も許す。ヘボン式の慣用（`matcha`）に合わせたもの。
- 促音の解決は「次のセグメント」を再帰的に見るため、`depth < 4` で再帰を打ち切っている。

検証結果：

| かな | 最短 | 受理される例 |
| --- | --- | --- |
| きって | 5 (`kitte`) | `kitte` / `kixtute` / `kiltute` |
| まっちゃ | 6 (`mattya`) | `mattya` / `maccha` / `matcha` / `maxtutya` |

`まっちゃ` で 4 通りすべてが通るのは、促音セグメントが `xtu` 系と重ね系の**両方**を
同時に候補として持ち、さらに拗音セグメントが `tya` / `cha` / `cya` を持つためである。

### 7.5 拗音の分解打ち

`FUSED` に `きゃ: ['kya']` があり、同時に `BASE['き']` と `BASE['ゃ']` も存在する。
`segmentsAt()` は融合（len=2）と単独（len=1）の**両方**を候補として返すため、
2 つの経路が並行して生きる。

`きゃく` で `k` → `i` と打った場合の観測値：

```
unitIndex = 1        // 「き」が確定
expected  = {l, x}   // kya 経路は k の次に y を要求するため、i で死んだ
remaining = xyaku
```

`k` を打った直後は `kya` 経路（次は `y`）と `ki` 経路（次は `i`）の両方が生きており、
`i` を打った瞬間に前者だけが落ちる。使い手から見ると「どちらで打ってもよい」であり、
内部では単に生存状態が絞られているだけ、という構造になっている。

### 7.6 最短打鍵数の算出

`_computeMinLen()` は後ろから前への DP で、位置 `i` から末尾までの最短ローマ字長を求める。

```
min[n] = 0
min[i] = min over セグメント( 最短つづり長 + min[i + seg.len] )
```

`totalKeys = min[0]`。これは `engine.js` の `progress`（進捗バー）の分母と、
`kids.js` のボス HP の計算に使われる。
`remaining()` は現在の状態集合の中から「打ち切るコストが最小」の状態を選び、
そこから貪欲に最短経路を辿って残りローマ字を組み立てる。
複数経路が生きている間も、ヒント表示は常に1つに定まる。

- **教材の差し替え**。`src/data/ja.js` などを置き換えれば教材は変えられるが、
  編集用の UI は無く、ファイルを直接書く前提になっている。
- **印刷用の結果**。紙で渡す運用がある場合、印刷用 CSS が要る。
